### Registro di verifica di conformità

Il file `registro-verifica-conformita-ntc2018.csv` è l'unica fonte operativa locale per il processo VC. Ha una riga per ciascuno dei 379 file normativi vivi indicizzati in `capXX/`: capitoli `x`, sezioni `x.y` (introduzione o sezione autonoma) e file naturali `x.y.z`. Sono tredici colonne: `paragrafo`, `titolo`, `n.`, `apri_md`, pagine dei due PDF, stato e data VC, prossima azione, evidenza, note, `procedura_vc` e `agente_vc`. `procedura_vc` distingue la revisione e la modalità usate; `agente_vc` identifica l’assistente responsabile, distinto dal modello. Le celle storiche vuote indicano attribuzioni non ancora riscontrate, senza riclassificare verifiche precedenti. Usa il punto e virgola ed è codificato UTF-8 con BOM. I 311 file `x.y.z` conservano l'indice interno; i file `x` e `x.y` no, finché non si decide di generarli.

Quando una riga viene promossa a `VC-OK`, la sua `prossima_azione` diventa sempre `Nessuna sul file: VC conclusa sullo snapshot registrato.`. La colonna descrive l'azione residua sul file della riga e non deve rinviare allo scope successivo; la prossima VC da aprire resta nel `TODO.md`, nel registro di revisione del capitolo e nella scheda dello scope appena chiuso. Il linter verifica questa convenzione.

Gli stati ammessi sono `VC-OK`, `IN-CORSO`, `DA-RICONFERMARE`, `DA-RIFARE` e `MAI-FATTA`. `DA-RICONFERMARE` distingue i paragrafi che avevano già superato G7 sul precedente insieme documentale; `DA-RIFARE` raccoglie gli scope sospesi, scaduti o chiusi con rilievi. Al 2026-08-27 il registro contiene 4 righe `VC-OK`, 37 `DA-RICONFERMARE`, 20 `DA-RIFARE` e 250 `MAI-FATTA`.

Le colonne delle pagine aggregano le pagine fisiche 1-based già attribuite alle unità del vecchio inventario. Per 51 file il precedente rilevamento non aveva individuato automaticamente una pagina della Circolare: il campo resta vuoto e la lacuna è dichiarata in `note`, senza assegnare valori presunti.
